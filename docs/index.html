Principles

The site is dressed as an MS-DOS shell and an EGA-era PC game: Windows 1.0 menu bars, Directory Commander info panels, Carmen Sandiego split screens, the 16-color palette. The chrome is retro. The reading is not.

  1. Chrome is nostalgic, prose is modern. Pixel type and EGA color live in bars, titlebars, panels and badges. Article text uses Atkinson Hyperlegible at 18px, 1.7 leading, and a 68ch measure.
  2. Hard edges, hard shadows. 2px borders, square corners, and a 6px offset shadow with no blur.
  3. Semantic tokens only. Components never use --ega-* directly. They use slots like --titlebar-bg, which change with the system color scheme.
  4. Decoration stays out of the accessibility tree. Titlebar filenames, the C:\> prompt and the > bullets are all aria-hidden or CSS-only.
  5. No theme switcher. Light and dark follow prefers-color-scheme. High-contrast, reduced-motion and forced-colors preferences are respected too.

      Menu bar & status bar

      The site header (top of this page) is a Windows 1.0 menu bar. The underlined letters are visual only, styled with .hotkey; there are no accesskey bindings to clash with assistive tech. The current page gets aria-current="page" and inverts. The footer (bottom of this page) is a DOS status bar with no indicators. Below 36em the menu bar collapses into a Menu button with a dropdown (assets/menu.js). It's a disclosure: aria-expanded on the button, and Escape, an outside click or tabbing away closes it. Without JavaScript the links simply wrap. Its last cell is the red “Press H for Help” cell.

      Code

      Code blocks are styled as a QBasic / MS-DOS EDIT screen in both schemes. microlighter highlights them with the CSS Custom Highlight API, so there are no token spans in the DOM. The theme is the --syntax-* tokens in style.css; their contrast is in the color table above. The base layout loads the runtime only when the page has a pre > code and the browser supports CSS.highlights. Otherwise code stays plain, readable text. Grammars load on demand from /assets/microlighter/grammars/, which Eleventy copies from node_modules. Every <pre> gets tabindex="0", so keyboard users can scroll wide blocks.

      Accessibility

      • Contrast: every text pair in the color table meets WCAG AA (4.5:1), and most meet AAA. Use the table above to check new tokens before shipping them.
      • Focus: a two-tone ring (--focus-ring outline plus --focus-halo shadow) stays visible on every surface, including the yellow, blue and cyan bars. Tab through this page to see it.
      • Skip link: the first tab stop on every page jumps to <main>.
      • Motion: nothing on the site animates. With prefers-reduced-motion, animations and transitions are also turned off globally as a safety net.
      • High contrast: with prefers-contrast: more the desktop dither is removed and muted text goes to full strength. In forced-colors mode, badges, tags and panels get system-color borders.
      • Landmarks: banner, a labelled main nav, main, and a labelled footer nav. Sidebar panels are sections labelled by their headings.
      • Reflow: no horizontal scrolling at 320px. Long URLs in link posts wrap anywhere.
